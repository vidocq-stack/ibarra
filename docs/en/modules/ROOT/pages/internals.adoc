== Output writers (implemented)

`BufferedJspWriter` acquires the response writer only when output must be sent.
It uses a character buffer (8192 characters by default), flushes on overflow
with `autoFlush=true`, and throws `IOException` on overflow otherwise.
`clear()` fails after flushing; `clearBuffer()` discards pending buffered
output. Closing flushes and closes the destination.

`BufferedBodyContent` captures tag output without flushing to its enclosing
writer. The body is unbounded, can be read or copied repeatedly, and can be
cleared between iterations. Nested bodies remain independent. Its inherited
`flush()` always throws `IOException`; closing never closes the enclosing writer.

Both classes are internal and request-owned. They introduce no module exports,
runtime dependencies, shared state or handler pooling.

== Page context and factory (implemented)

`IbarraPageContext` stores page attributes locally and delegates request, session
and application scopes to the Servlet API. Session access is opt-in. Nested
body pushes update the implicit `out` attribute; pops restore the previous writer.
Includes route through the current writer, preserving output order and body
capture. Forwards discard pending output and reject committed responses. Error
pages receive Servlet error attributes and the Pages exception attribute; after
commitment they are included. Release drops request state without pooling.
Page code flushes or closes output before releasing its context.

`IbarraJspFactory` allocates fresh request contexts and shared application contexts.
The future container binding installs it with `JspFactory.setDefaultFactory()`
and removes application contexts only after requests have drained.

== Application EL context (initial implementation)

Application resolver registrations freeze atomically on first context creation.
Provider lookup is lazy and happens once per application. Each page caches its
EL context before notifying listeners so callbacks can retrieve it safely. A
failed callback clears the cache for a later retry. Application and standard
collection/bean resolvers precede the scoped-attribute resolver.

The full Pages implicit-object/import chain, real Peano evaluation and generated
expressions remain I3 work. Unit tests use a concrete EL factory double.

== Translation pipeline (planned)

The first parsing stage exists; translation semantics and generation are still planned.

. Parse the page (standard or XML syntax) into a page model, applying `jsp-config` property groups and TLDs.
. Generate the Java source of an `HttpJspPage`; page expressions are compiled by Peano's build-time compiler.
. Compile with `javax.tools` in the build JVM; emit a page index registered through `ServiceLoader`.

A Class-File API back end for scriptless pages (no `javac` at all) is a later option.

== Page parser (implemented)

`PageParser` consumes decoded source strings and produces immutable nodes for
template text, EL expressions, directives, scripting and nested elements. It
selects XML syntax for `.jspx`/`.tagx` and a document-level JSP root; callers can
explicitly select syntax and supply EL defaults through `ParserOptions`.
Page/tag EL directives apply to the whole document.

Standard syntax preserves ordinary markup and HTML comments while removing
JSP comments. XML syntax uses the JDK StAX parser, recognizes the JSP namespace
by URI, decodes XML character references and CDATA, and preserves whitespace
inside `jsp:text`. Node locations refer to the original source, including before
XML decoding, with one-based lines and UTF-16 columns. `PageParseException`
provides the location separately from its build-readable message.

The module requires only `java.xml` and exports only the parser/model API.
Attribute interpretation, include expansion, encoding detection, full semantic
validation and generation are later stages. DOCTYPE declarations and external
entities are unsupported in this initial parser; no external documents are read.

== Foy integration

Foy will expose a JSP-engine SPI: deploy-time callback with the `JspConfigDescriptor`, the servlet mapped to `*.jsp`, the servlet backing `addJspFile`, and the TLD-declared listeners. Without Ibarra, Foy keeps working with JSP unmapped.

== AOT compatibility

Target: no compiler and no class loading by name at run time in production, no reflection in generated code, no `opens`.
