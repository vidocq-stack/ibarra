= Official TCK runner
:description: Build-side Arquillian WAR adapter for Jakarta Pages 4.0 on modular Foy.

`ibarra-tck` is unpublished and enters the reactor only under `-Ptck`.
`-Ptck,tck-official` additionally resolves the official Pages 4.0.0 suite.
See xref:tck.adoc[TCK status] for the measured baseline and certification limits.

[source,bash]
----
./run-official-tck-pages-4.0.sh smoke
./run-official-tck-pages-4.0.sh all
./run-official-tck-pages-4.0.sh -Dtest=ee.jakarta.tck.pages.api.jakarta_servlet.jsp.jspwriter.URLClientIT
----

The script verifies distribution checksums, preserves the upstream Maven POM,
installs the non-Central artifacts, clean-installs Ibarra, tests the adapter,
and runs the requested official tests. Java 25, Maven 3.9.16 and Python 3 are
required. Local ZIP overrides and skip switches are documented in
link:{repo-ibarra}/src/branch/main/ibarra-tck/README.md[the runner README].

== Test tooling dependencies

The runner uses Arquillian container SPI, ShrinkWrap, JUnit and the official
`jakarta.tck:jakarta-pages-tck:4.0.0` jar with its original dependencies,
including `jakarta.tck:common`, `runtime`, `libutil`, signature tooling,
Apache HttpClient and `javatest:javatest:5.0`. This last tool is extracted from
an earlier Eclipse distribution because the Pages 4.0 ZIP omits it.
Only that tool is used from the older distribution; all tests are Pages 4.0.
These dependencies are test-only and never enter application artifacts.

== Runtime isolation

The build-side adapter precompiles each WAR as a named application module,
then launches Foy/Chappe in a separate process on the module path.
The server rejects the presence of `java.compiler` or either compiler module;
Peano reflection remains denied. Application packages have no added exports
or opens. Multiple WARs have independent ports, lifecycles and resource roots.
Retained server logs and Surefire reports are in `ibarra-tck/target`.

Root web.xml property groups are parsed at build time, with matched scalar settings,
ordered preludes/codas and legacy EL defaults. The runner explicitly selects
`PagePrecompiler.precompileDeployment`: valid pages compile normally, while genuine
parse/generation/javac failures produce direct error servlets that throw on request.
The full diagnostic is retained in `translation-errors.txt`; error messages are
bounded without splitting Unicode characters. Previous generated classes cannot
satisfy new incremental dependencies. Normal packaging remains fail-fast.

[source,java]
----
var groups = new JspConfigurationParser().parse(
        "/WEB-INF/web.xml", Files.readAllBytes(webRoot.resolve("WEB-INF/web.xml")));
var report = new PagePrecompiler().precompileDeployment(
        webRoot, classes, modulePath, null, new GenerationOptions(groups, Map.of()));
// report.pages() includes routable valid/error pages; report.failures() is immutable.
----

These APIs belong to the build-only `io.vidocq.ibarra.compiler` package.
Global property keys, booleans, encoding and buffer capacity are validated before
individual page recovery, even for an application with no pages. Invalid global
settings leave previous generated output ownership intact.

The adapter explicitly rejects libraries, Servlet component factories and
initializers that it cannot yet adapt. Invalid global configuration and TLD
metadata still abort deployment. These remain visible full-suite errors.
