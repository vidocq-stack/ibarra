= Usage
:description: Intended usage patterns of Ibarra — precompiled pages, custom tags, tag files, development mode. In design.

[.lead]
Nothing on this page works yet. It lists the usage patterns Ibarra is designed for, in the order the milestones deliver them.

== Precompiled pages (default)

`ibarra-maven-plugin` translates every `.jsp` / `.jspx` and tag file of the web application during the build and generates a page index. Foy maps `*.jsp` to Ibarra's servlet, which looks pages up in the index — no class loading by name, no compiler at run time.

== Custom tags and tag files

TLDs (`WEB-INF/**/*.tld`, `META-INF/**/*.tld` of libraries) are read at translation time: generated code instantiates tag handlers and calls their attribute setters directly. Tag files under `WEB-INF/tags` are compiled like pages.

== `jsp-config`

`jsp-property-group` settings from `web.xml` (encoding, `el-ignored`, `scripting-invalid`, preludes and codas, buffer, `error-on-el-not-found`…) are applied at translation time, using the descriptor Foy parses.

== Development mode (degraded)

A page without a precompiled class can be translated on first request through `javax.tools`. This needs the `java.compiler` module, logs a warning per page, and is off by default in production.

== Out of scope

JSTL (the Jakarta Standard Tag Library) is a separate specification and is not provided by Ibarra.
